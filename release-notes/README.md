# Release notes

One note per completed task (issue/PR), written for someone **new to the project**. Each note
explains what was done, why, and exactly how to verify it — in plain language.

## Convention

- File name: `<milestone-id>-<slug>.md` (e.g. `m0.2-cpp-toolchain.md`).
- Add the note in the same PR as the work it describes.
- Structure: **What I did** (numbered, newcomer-friendly) and **How to test and confirm**
  (copy-pasteable commands + what success looks like).
- Link the issue and PR at the top.
