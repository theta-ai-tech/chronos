# M0.2 — C++ toolchain: CMake, profiles, lib + unit-test target

- **Issue:** #2
- **PR:** #50
- **Milestone:** M0 — Repo, toolchain & boundary

## What I did

1. **The context:** Chronos's performance-critical part ("hot path") is written in C++. M0.2's
   job was to set up the C++ build system — no trading logic yet, just the scaffolding that
   lets C++ code compile, link, and run tests.
2. **Picked the tools** already on the machine: CMake 4.3.1 (build configurator), AppleClang 16
   (C++ compiler), Ninja 1.13.2 (fast builder). Pinned the language to **C++20**.
3. **Added a top-level `CMakeLists.txt`** — the root recipe that tells CMake how to build the
   project, which standard to use, and which sub-folders contain buildable code.
4. **Created three build "profiles"** (flavors of the same code): `Debug` (slow, with safety
   checks, for development), `Release` (fast/optimized), and a custom **`Benchmark`**
   (optimized but deliberately *not* tuned to this specific CPU, so latency measurements are
   reproducible on the bench machine — ties to ADR-0002).
5. **Made warnings fatal by default** (`-Werror`): the compiler refuses to build if the code
   has even minor issues. This keeps quality high from day one.
6. **Added an optional "sanitizer" mode** (`CHRONOS_SANITIZE`): turns on tools that catch
   memory bugs and undefined behavior at runtime — invaluable for C++.
7. **Built one placeholder library, `chronos_core`** (a trivial `version()` + `engine_alive()`),
   purely to prove the toolchain compiles and links real C++ from the `core/` module.
8. **Wrote a tiny test framework** (`tests/support/microtest.hpp`, ~60 lines) instead of
   downloading one. Why: the project rule is "builds must work without internet access," so I
   vendored a minimal harness rather than fetching Google Test.
9. **Added a unit-test program** (`chronos_unit_tests`) wired into **CTest** (CMake's test
   runner), with two trivial passing tests.
10. **Wrote `BUILDING.md`** documenting how to build, the profiles, and the options — plus a
    short build section in the README.
11. **Updated `.gitignore`** so build output (`/build/`) never gets committed.
12. **Verified everything locally** before pushing: all three profiles + the sanitizer build
    each configured, compiled, and passed tests; I also proved `-Werror` genuinely rejects a
    warning (so the quality gate is real, not decorative).
13. **Committed on a branch** `feat/m0.2-cpp-toolchain` and opened **PR #50**, which auto-closes
    issue #2 when merged.

## How to test and confirm (copy-paste, ~30 seconds)

`make cpp-profiles-check` configures, builds, and tests Debug, Release, Benchmark,
sanitizer, and Ninja Multi-Config builds under the enforced compiler policy.
CI selects the pinned Clang 18 compiler explicitly; AppleClang 16 remains the supported
platform compiler for local macOS development.

14. **Get the branch:** in the project folder, run
    `git fetch origin && git checkout feat/m0.2-cpp-toolchain`.
15. **Configure the build:** `cmake -S . -B build -G Ninja` — this reads the CMake files and
    prepares a `build/` folder. You should see a line ending
    `Chronos 0.0.1 | profile=Debug | werror=ON | sanitize=OFF`.
16. **Compile:** `cmake --build build` — should finish with
    `Linking CXX executable tests/chronos_unit_tests` and no errors.
17. **Run the tests:** `ctest --test-dir build --output-on-failure` — expect
    `100% tests passed, 0 tests failed out of 1`.
18. **See the test output directly (optional):** `./build/tests/chronos_unit_tests` — prints
    `[ PASS ]` twice and `RESULT OK`.
19. **Try another profile (optional):**
    `cmake -S . -B build-bench -G Ninja -DCMAKE_BUILD_TYPE=Benchmark && cmake --build build-bench`
    — confirms the optimized benchmark profile also builds.
20. **What "success" means:** all three commands in steps 15–17 finish without errors and the
    test run reports 100% passed. That's the whole acceptance bar for M0.2 ("clean build in all
    three profiles; sample unit test runs").

## Review follow-ups

An independent review pass (verdict: approve-with-nits) prompted these hardening fixes, all on
this same branch:

21. **Made the sanitizer actually fail on undefined behavior.** UBSan defaults to "recover"
    mode: it *prints* a violation but the program keeps running and exits `0`, so a bug would
    silently pass the tests. Added `-fno-sanitize-recover=all` so the first violation aborts —
    proven: without it a signed-overflow probe exits `0`, with it the same probe exits `134`.
22. **Made the test harness exception-safe.** A `TEST_CASE` that throws is now caught, counted
    as a failure, and attributed to its case — instead of terminating the whole run and skipping
    the remaining tests.
23. **Fixed the status line for multi-config generators** (was printing `profile=` blank; now
    says `multi-config`), documented that the warning flags are GCC/Clang-only, and ignored
    local clangd/CMake-preset artifacts in `.gitignore`.
