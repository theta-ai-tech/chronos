# M0.3 — Python toolchain: project, lock, lint, format, test runner

- **Issue:** #3
- **PR:** #51
- **Milestone:** M0 — Repo, toolchain & boundary

## What I did

1. **The context:** Chronos uses C++ for the measured hot path, but the application layer,
   research tooling, local API, and operator-facing workflows are Python. M0.3's job is to make
   that Python side real enough to install, lint, format, and test before Python starts calling
   into C++ in M0.4.
2. **Added `pyproject.toml`** as the single Python project definition. It declares the
   `chronos-engine` package, requires Python 3.9 or newer, and keeps runtime dependencies empty
   for now because this milestone is infrastructure only.
3. **Chose `uv` for dependency management and locking.** The lockfile records the exact versions
   of the Python tooling used by this repo, so contributors do not need globally installed
   `pytest` or `ruff`.
4. **Added a tiny importable Python package** in `python/chronos/`. It intentionally exposes only
   `__version__`; no domain logic belongs in M0.3.
5. **Added a Python test runner path** at `tests/python/`, with one smoke test proving the package
   can be imported through the project metadata.
6. **Configured lint and format tooling** through Ruff in `pyproject.toml`. The lint rule set
   covers syntax/import errors, import sorting, modern Python upgrades, and common bug patterns.
7. **Added one aggregate Python gate, `make python-check`.** It runs the sample test, lint check,
   and format check through `uv` so the milestone can be verified with one command after sync.
8. **Updated the build docs and README** so the C++ and Python setup commands are visible from
   the top level.

## How to test and confirm

`make python-build` verifies that the source distribution and wheel contain only the
intentional package sources and no local worktrees, build output, or journal artifacts.

8. **Install/sync the locked Python tooling:**
   `uv sync --group dev`.
9. **Run the Python gate:**
   `make python-check`.
   Success means pytest reports `1 passed`, Ruff reports `All checks passed!`, and Ruff confirms
   the Python files are already formatted.
10. **Optional individual commands:** the aggregate target runs
    `uv run --group dev pytest`, `uv run --group dev ruff check .`, and
    `uv run --group dev ruff format --check .`.
11. **What "success" means:** a clean checkout can reproduce the Python environment from
    `uv.lock`, import the placeholder package, run the Python test suite, lint the repo, and check
    formatting without relying on globally installed Python tools.
