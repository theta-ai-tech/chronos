# M0.1 — Monorepo skeleton + per-module owner stubs

- **Issue:** #1
- **PR:** #49 (merged)
- **Milestone:** M0 — Repo, toolchain & boundary

## What I did

1. **The context:** Chronos is being built as a single repository ("monorepo") holding many
   modules. Before writing any code, the folders and their ownership rules need to exist so
   everything lands in the right place. That's all M0.1 does — structure, no logic.
2. **Created the top-level folders** from the architecture's documented tree: `contracts/`,
   `core/`, `accounting/`, `adapters/`, `runtime/`, `applications/`, `strategies/`,
   `research/`, `tests/`, `tools/`, `config/`.
3. **Created the second-level submodules** inside each (e.g. `core/market_state/`,
   `adapters/market_data/`), 52 in total.
4. **Added an "owner stub" README to every module** stating its owner, runtime plane,
   language, what it may depend on, and what it must *not* depend on — encoding the
   architecture's dependency rules as documentation from day one.
5. **Added a root `README.md`** orienting a newcomer: the folder map, where the authoritative
   docs live, and the dependency direction.
6. **Why owner stubs matter:** they make the "who owns what" boundaries explicit before code
   exists, so later work can't accidentally blur responsibilities.
7. **Addressed a review comment:** the reviewer noted `docs/runbooks/` was in the documented
   tree but missing (git doesn't track empty folders), so I added a tracked stub there.
8. **Committed on a branch and opened PR #49**, which was reviewed and merged.

## How to test and confirm

1. **On `master`, list the top-level folders:** `ls -d */` — you should see `contracts/`,
   `core/`, `accounting/`, `adapters/`, `runtime/`, `applications/`, `strategies/`,
   `research/`, `tests/`, `tools/`, `config/`, plus `docs/` and `planning/`.
2. **Check a module's owner stub:** `cat core/README.md` — it should describe `core/` as the
   C++ hot plane and list its submodules.
3. **Confirm every module is documented:** `find . -name README.md | wc -l` returns 60+.
4. **What success means:** the folder tree matches the architecture doc and each module has a
   README. There is no code to run yet — that's expected for M0.1.
