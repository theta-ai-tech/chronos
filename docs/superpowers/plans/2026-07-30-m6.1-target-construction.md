# M6.1 Target Construction Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the deterministic single-portfolio authority that converts a bounded accepted recommendation set and an immutable portfolio snapshot into an absolute target, an explicit no-change, or a typed construction rejection.

**Architecture:** Extend the existing immutable M5 recommendation with its accepted run/strategy/instrument/listing scope, then add a standalone `chronos_portfolio` target under `core/portfolio`. The authority accepts only explicit deterministic inputs, canonicalizes recommendation evidence, performs checked fixed-point arithmetic, and never depends on risk, execution, accounting, adapters, storage, telemetry, or host time.

**Tech Stack:** C++20, CMake/Ninja, microtest, Python verifier/pytest

## Global Constraints

- The approved design in `docs/superpowers/specs/2026-07-30-m6.1-target-construction-design.md` is authoritative.
- Use test-driven development: add a failing focused test before each production behavior.
- Keep `TradeRecommendation` construction private to `RecommendationAuthority`; do not introduce a test-only or public forging API.
- Keep M6 tests in `tests/unit/feature_runtime_test.cpp`, where the existing end-to-end M5 fixtures can produce genuine recommendations.
- A zero aggregate means no change, not flattening. `explanatory_delta_units` is informational and non-executable.
- Invalid policy/configuration is a pre-admission API failure. Every obligation admitted under valid policy produces exactly one terminal domain outcome.
- Recommendation order must not affect semantic output or identity. Duplicate recommendation or signal IDs reject; they are never silently deduplicated.
- `chronos_portfolio` may link only contracts/build-policy/recommendation targets. It must not gain risk, reservation, execution, adapter, accounting, storage, telemetry, application, or UI dependencies.
- Preserve all existing M0-M5 behavior and cumulative gates.
