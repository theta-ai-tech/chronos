# M6.2 Minimal Risk Decision Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add one deterministic, fail-closed risk-policy authority that consumes
an M6.1 absolute target and immutable evidence, then returns an approved,
modified, rejected, unavailable, or admission-rejected terminal without
performing reservation or execution.

**Architecture:** `chronos_risk` is a focused C++ static library downstream of
`chronos_portfolio`. One pure `MinimalRiskAuthority::evaluate` call validates
policy, admission facts, run/policy activation, and safety snapshots in fixed
order before applying the `QuantityOnlyV1` projected-exposure model. A separate
Python/CMake gate proves the risk target cannot acquire downstream capabilities.

**Tech Stack:** C++20, checked integer/fixed-point value objects, SHA-256 domain
identities, CMake/Ninja/CTest, Python 3.9+, pytest, Ruff.

## Global Constraints

- Follow `docs/superpowers/specs/2026-08-01-m6.2-minimal-risk-decision-design.md`.
- `RiskDecision` has only approved, modified, and rejected semantic
  dispositions; unavailable and admission rejection are separate terminal
  types.
- Actual run mode comes only from validated `RunRiskContext`, never from the
  target or an unvalidated caller flag.
- Missing, stale, future, recovering, gapped, invalid, unavailable, or
  incompatible required evidence never authorizes a target.
- `QuantityOnlyV1` computes `requested_delta = target - account_current` and
  `requested_projected = projected_before + requested_delta` with checked
  signed arithmetic.
- Modification must reduce both absolute projected exposure and target movement
  under the complete proof; otherwise reject.
- A decision expires no later than its source target.
- M6.2 records but never advances `risk_sequence`; M6.3 owns reservation and
  current reservation eligibility.
- All IDs include complete semantic inputs in explicit canonical order. Do not
  use host time, pointer identity, unordered iteration, or binary floating point.
- Keep `chronos_risk` dependent only on `chronos_contracts`,
  `chronos_portfolio`, `chronos_options`, and `chronos_warnings`.
